# Claim provenance and confidence

- `SOURCE`: Documented in the five PDFs. Details can be draft rather than approved.
- `PROPOSED`: Engineering direction in Architecture/ERD not confirmed as code or business decision.
- `UNVERIFIED`: User's new repositories, actual tested features and real API endpoints cannot be accessed yet.
- `DECISION_REQUIRED`: Explicitly marked unresolved by source documents.
- `CODE_VERIFIED`: Reserved for future code inspection with path/branch/SHA; none for these three repos as of creation.

Keep screenshots and older demo repo code as visual or historical references only; never represent them as latest `naanga7peru` implementation.
